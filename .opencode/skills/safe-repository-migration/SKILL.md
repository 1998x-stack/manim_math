# Safe repository migration / 可回退文件整理

## 何时使用

用户要求按 category 归档、移动文件、清理重复资源、建立新目录、合并相同知识点或升级发布管线。先读 `docs/architecture/migration.md` 和 `docs/architecture/audit.md`；旧目录不是简单垃圾目录。

## 迁移边界

文档可在完整保留原内容的同时移动到 `docs/{curriculum,prompts,math,engineering}/`，旧位置提供跳转入口以维持链接。**课程场景和媒体仍有运行依赖**：`assets/build_catalog.py` 固定扫描旧目录并以路径生成 topic ID，`deploy-gallery.yml` 监听旧 Python 路径，现有 MP4 链接可能已对外公开；不得只按名称直接 `git mv` 后就宣称迁移完成。

## 操作协议

1. 盘点精确原路径、文件类型、哈希、引用和用途。分类文件为源代码、教学文档、数学参考、程序配置、资源、渲染中间产物、正式出版物。确认哪些可再生成、哪些是唯一原件。未知归属放待审核清单。
2. 列出逐项旧→新路径映射、目标类别、关联 topic/scene/artifact、索引字段/脚本/网页/CI 需修订的位置；所有媒体先核对作者权利和分发 URL。
3. 优先做文档和独立规范迁移：新路径放置原样内容，旧路径保留可点击跳转，更新入口及交叉引用；历史归档仍保持可取用。
4. 源代码迁移前，先完成稳定 ID/legacyId、显式 Scene 类、画廊/工作流迁移支持，再按少量无外部链接的样例验证场景导入、渲染和 catalog 差异。
5. 对原始音视频、PDF、音频、图像和已有 `*_finish.mp4` 不批量搬迁、删除、覆盖或重新编码；资产托管迁移需独立审核和授权。
6. 分批提交、每批有路径映射与可观察验收，失败则回退该批全部关联变更；在报告里区分“已迁移文档”和“仅设计的源代码/媒体迁移”。

## 完成条件

目录导航和旧链接正常，受影响的 Python import/资源相对路径更新，生成索引的 ID/URL 有明确的前后对照，相关 CI 与预览运行通过。仅通过纯文本结构检查并不足以宣布视频迁移无回归。
