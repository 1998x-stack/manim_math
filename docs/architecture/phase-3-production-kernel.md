# 第三阶段：数学动画生产内核与可信交付

> 状态：**设计与验收规范，非生产功能已实现**。第二阶段 PR #2 已合并，但 Issues #4–#6 的持久身份注册、v2 Schema、双索引和试迁尚未验收。第三阶段设计及独立数学原型可提前开展，任何生产集成须先通过 G0。

## 目标及架构不变量

北极星：每个新建或改动的作品能够从 `LegacyEntry/Topic → ProofSpec → Storyboard → Scene → Build → Artifact → Publication` 追溯到输入、版本、验证结论与证据。旧内容不被推定已完成验证。数学证明、数值检查、动画渲染、视觉审阅、许可审核及 URL 检查分别给出状态，不能互相替代。

不可变约束：保留旧 ID/视频路径/公开链接；Scene 移动不能导致 topic_id/scene_id 改变；未知必须标记 unknown/needs_review/not_run 而不是 passed；不得以文件名猜测绑定媒体；原始视频不自动删除、覆盖或迁移；原 Gallery 在完整影子对比前不切换数据源。

## 关键依赖门禁 G0

必须先完成第二阶段：534 条旧索引 ID 的持久映射和双向查询、改名模拟身份不变；已实现 v2 JSON Schema/语义校验及不明引用阻断；AST 可明确发现 Scene，歧义标记 needs_review；旧版/新版 catalog 影子比较和旧 Gallery URL 实际兼容；一个试点的本地渲染/数学/视觉证据。未满足时，只能合并独立纯数学模块、测试规范和原型，不可写入 authoritative v2、迁移媒体或切换 Gallery。

## 分层设计

- `src/manim_math/math/`：纯 Python/NumPy/SymPy 可选依赖，定义域/几何量/算法/不变量，不导入 Manim，不改全局配置。
- `src/manim_math/visual/`：Manim 适配、坐标映射、Text/MathTex 与可复用图元。不能包含数学定理的证明逻辑。
- `src/manim_math/production/`：RenderProfile、Build 输入指纹、执行与证据 manifest；发布和后期属于独立步骤。
- `scenes/`：只引用经过检验的 math 接口、Storyboard 与视觉图元；保留原始 legacy Scene 的兼容入口。
- `catalog/v2/`：阶段二确立的稳定身份与实体数据为权威源；画廊只消费受版本控制的导出数据。

## 工作包及可核验完成条件

**T3.0 G0 preflight（最高优先级）**：生成机器可读依赖检查结果，每项包含 issue/PR/commit、测试日志、通过或阻断及审核人。G0 未过时标记 blocked，不伪称正式开始生产集成。

**T3.1 Math kernel**：独立抽取欧拉线纯计算，定义坐标单位、输入 finite 检查、退化/近退化阈值及明确异常。现有 `external/euler_line.py` 在近退化时把重心当外心，必须先形成失败回归样例，再分步替换；零长度垂足/垂直平分线不得产生有效输出。正常/直角/钝角/等腰/等边/共线/重复点/近共线/尺度变化至少覆盖；测试外心等距、三高关系、`H=A+B+C−2O`、`GH≈2 OG`；等边时 OG=GH=0，不写未定义比值 1:2。随机性质测试记录 seed，必须有独立公式或几何定义交叉验证，避免同一实现自证。

**T3.2 Storyboard 与图元**：shot_id 映射学习目标、数学 assertion_id、画面对象、动作、字幕、时长预算、抽帧点、审阅状态。先实现 2–3 个被真实作品复用的组件，不为一次性画面制造通用抽象；字幕/公式混排遵守中文字体约束，时间线与 Layout 复核。验收：两类不同主题可使用相同图元而无场景特定分支；每个关键数学断言至少有对应镜头和审阅帧。

**T3.3 RenderProfile 与构建**：档案锁定画幅、像素、FPS、字体、背景、种子、Manim/FFmpeg/LaTeX/Python/依赖版本与平台；旧 1080×1920/9×16 为 legacy profile，不能静默改变旧作品。全局 config 通过子进程隔离或严格恢复。Build 保存源 commit、输入 hash、命令、退出码、耗时、日志、产物 hash（实际存在时）及失败原因。验收：相同输入的数据导出字节一致；在锁定环境下两次运行得到相同数学结果/预期规格；不强求跨平台 MP4 字节恒等。

**T3.4 多层 QA**：L0 Schema/引用/身份/静态安全；L1 数学定义域/性质测试/ProofSpec 人工或符号依据；L2 Scene 可加载/低清渲染/ffprobe；L3 关键帧人工审核/完整渲染/音轨/媒体来源和授权/真实公开 URL。状态取 passed/failed/needs_review/not_run，发布门禁只接受必需项全通过。注入坏公式、错误 Scene、缺字体、运动越界、损坏视频、悬空 ID、未知授权、旧 URL 404 时必须阻断或标记待审，而不是通过。低清渲染不证明数学定理；自动无报警不等于画面通过。

**T3.5 Pilot E2E**：选一项欧拉线作为几何回归试点，再选一个小学或代数专题确认跨领域复用；每个产出 ProofSpec/Storyboard/Scene/Build/Artifact/Publication 链的证据，旧路径/ID/URL 保留。试点可在本地依赖完整环境低清和正式渲染、人工关键帧审阅、ffprobe 检测。旧数据兼容通过才允许逐批迁移。

**T3.6 效率闭环**：记录每道 gate 执行时长、失败类别、重渲染次数、复用组件使用与缓存命中，先测基线再定改进指标；按输入 hash/依赖图选择性重建，数学模型、字体或 profile 更改必须失效对应下游缓存。单一错误由实体/shot/build 精确定位并建立回归样例；不要用新增 Prompt 替代源码修复。

## 发布验收（DoD，必须全部满足）

1. G0 有已合并代码及可复核测试记录；534 条 legacy alias 可查、稳定 ID 不漂移，旧画廊和真实公开 URL 不回退。
2. 至少两个跨领域试点完整串联 Math/ProofSpec→Storyboard→Scene→Build→Artifact→Gallery，记录输入哈希、版本、状态和审核证据；旧视频不被推定再验证。
3. 数学合法/非法/边界/极端尺度和性质测试通过，未定义对象不能由伪造有效坐标替代；ProofSpec 已审阅且数值测试不冒充证明。
4. 故障注入能有效拦截错误公式、错误 Scene、越界/缺字、坏视频、未知许可、失效 URL 和悬空 ID；CI 未执行的门禁只能显示 not_run。
5. 两个试点有真实渲染和 ffprobe 日志、人工视觉审阅、构建溯源及可取得产物的 SHA-256；同输入目录导出两次字节相同。
6. 迁移和发布有独立回退路径，任何 blocker 均不允许 `ready_to_publish`；媒体版权/授权未知不自动宣称通过。

## PR 实施与回退策略

各工作包独立小 PR：先补失败测试和设计契约，后加实现与兼容适配，再放开画廊/生产入口。每个 PR 明确影响范围、依赖门禁、执行命令、负例验证、尚未验证项和 git revert 路径；不改写历史、不批量移动 MP4/MP3/PDF。AI Skills 仅提出候选代码/推导/分镜，不能自行签署人工数学证明、画面审核或媒体许可通过结论。
