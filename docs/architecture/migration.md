# 路径整理、迁移与回退

## 已实施（文档阶段）

将原有 `docs/` 混合文档按 `curriculum/`、`prompts/`、`math/geometry/`、`engineering/references/` 分组；旧路径保留指向新路径的 Markdown 入口。原文件内容采用原 blob SHA 引用，避免迁移时意外修改内容。新增 `docs/README.md` 提供分类索引。历史 `.skill` 文件暂保留在 `skills/`，以免影响已有用户安装方式。

## 尚未实施（课程源文件与大型媒体）

1. 为每个旧 Topic 建立 `topic_id` 和 `legacy_id` 映射，记录旧路径、目标路径、Scene 类、现有视频 URL 和索引计数；同名/多场景文件需要人工判别。
2. 扩展并测试索引器：解析所有 Scene 子类而非取第一个类；引入显式 media manifest；以稳定 ID 替换路径哈希并在过渡期输出 `legacyId`。
3. 同步更新 `deploy-gallery.yml` 和前端路径路由，测试旧链接与预览；冻结或明确转发已公开的 URL。
4. 对一小组**不含被引用视频路径**的样例先移动；在独立分支比较迁移前后的 Topic、Scene、视频关联和生成目录，检查相对资源路径与 Python import。
5. 再按章节迁移其余源文件；不批量移动仓库历史中的 MP4、MP3、PDF。媒体存储策略（Git LFS、发行附件或对象存储）应先审查分发 URL、许可和成本。

## 回退机制

每批迁移独立提交并附 `old_path → new_path` 表；回退对应提交时同时恢复索引和工作流，不重写 Git 历史。迁移中若出现路径或 ID 无法兼容，停止该批、保留旧资源，禁止凭视频文件名自动删去所谓重复文件。

## 不可静默执行的操作

删除原始作品、自动覆盖 `_finish.mp4`、对全仓库运行清理脚本、变更现有 GitHub Pages URL、重写历史媒体、改变教材归属或几何结论。文档归类不表示上述更改已执行。
