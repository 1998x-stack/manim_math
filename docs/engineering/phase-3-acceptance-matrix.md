# 第三阶段质量门禁、证据与失败注入矩阵

> 本文定义未来验收标准，不代表仓库现有 CI 已覆盖以下检查。`passed` 只能由执行过且拥有证据的检查赋值。

## 0. 状态和证据契约

每个检查以 `(entity_id, entity_revision, gate_id, gate_version, inputs_sha256)` 为对象，记录 `status ∈ {passed,failed,needs_review,not_run}`、`executed_at`、`command` 或 `review_method`、`environment`、`evidence_uri`、`reviewer`（若为人工门禁）、`reason`。机器执行与人工审批字段不能混用；输出缺失、工具不可用时标 `not_run`；歧义时标 `needs_review`，不可自动提升为 passed。历史作品导入时其证明/画面审核保留 unknown，而不是批量 passed。

**传播规则**：当前版本某必需门禁 failed 或 not_run → 禁止发布；needs_review → 需具名人工审阅并产生新证据；数据/代码/字体/Profile/输入变更 → 按依赖图使相关旧证据过期；仅有哈希相同且门禁版本、环境约束相容时可复用机器检查结果，不能无限期复用人工审阅结论。

## 2. 数学测试策略

先把 `external/euler_line.py` 的计算行为作为已知失败案例记录：退化三角形的 circumcenter 不应返回重心。对于输入 A,B,C，使用无量纲面积或长度尺度判断退化/近退化；输出允许明确异常或状态，不允许伪造有效外心。覆盖正常锐角/钝角/直角、等腰、等边、近共线、共线、重合、非常大/小尺度、非有限坐标；使用独立算法验证外心等距、重心定义、垂心高线垂直、九点圆心中点。等边三角形 O=G=H，距离关系 `GH=2 OG` 成立，但比值 `OG:GH=1:2` 是未定义 0:0，不得展示为普通比值。数值误差界以输入尺度、运算条件和输出量为依据，精确证明与有限采样结果明确区分。

## 3. 视觉审查证据

对每个关键 shot 提供 `shot_id`、目标公式或图形、预期起止时刻、至少一个静态检查结果及人工查看的关键帧；对连续移动对象采样时间区间（起止点、极值点和转场附近），自动越界只用于提示，人工复核公式排版、颜色辨识、缺字、重叠、数学图形和字幕语义。审核必须针对实际渲染产物的 hash，而不是仅针对源码。历史 9×16 设置和经验安全区域须按目标发布渠道的实际遮挡区域验证。

## 4. 产物与构建可复现

`Build` 记录输入引用、git commit、profile/依赖版本、字体清单或许可可公开名称、种子、构建命令、退出码、各 gate、日志与输出定位。正式成功前 `Artifact` 不得标记 published。连续两次生成的**目录 JSON**应字节一致；视频跨机器字节恒等不作为硬门槛，但要对比 ffprobe 元数据、选定关键帧视觉内容与适用误差。缓存在数学模型、Storyboard、字体、profile 或工具版本变化时失效，缓存命中不能直接复用过期的人审证据。

## 5. 试点与范围验收

优先一个真实几何专题（Euler Line，暴露退化与等边边界）+ 一个跨学段的数与代数/小学计数主题（检验通用布局与不同证明形式），先为两个专题做只读 manifest 再触碰旧 Scene。每个试点必须有已审阅 ProofSpec、Storyboard、可渲染 Scene、低清和正式 Build、原始/成片 Artifact、可用 Publication 或明确尚未发布；仅实际发布的作品须通过 P1 并声明公开访问。未发布试点可以完成内部 E2E，但不得宣称已上线 Gallery。

## 6. 评估优化是否真的有效

先记录当前两试点的场景 LOC/重复实现处、数学失败类型、从改动到首帧/成片耗时、视觉返工次数、执行门禁耗时、缓存与重渲染次数。优化后在**相同测试环境与任务集合**复测，报告原始数值及差值，不在无测量时承诺百分比。优先优化错误检出率、人工需要重复判断的步骤与失败定位精度，而非单纯增加 Skills 数量或 Python 抽象层。
