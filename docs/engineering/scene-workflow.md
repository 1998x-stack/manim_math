# 数学动画制作：从课程任务到发布的六阶段

适用：新增或修改一个数学教学 Scene。先读[文件地图](repository-map.md)定位实际输入，再按[分层 Prompt 规范](../prompts/authoring.md)处理历史 `prompt.md`。流程中的“检查”指必须取得实际证据，未运行的步骤只能记为未完成；完整验收标准见[质量门禁](quality-gates.md)。

## 0. 接收任务与确定知识点

核对受众、单一学习目标、教材版本（如已知）、先修知识、现有 `description.json` / `prompt.md` / `storyboard.md` / Scene；历史通用模板不可凌驾于已核实的数学条件。按 `prompt-to-scene` Skill 分离课程数据、视觉偏好、当前交付要求与待核验项。记录真实源码与 Scene 类名，不以文件名或 Python 文件中第一个类作为判断依据。

## A. 数学规格

明确已知、定义、变量及量纲、定义域、非退化约束、结论与反例；为每个会在动画中展示的数学事实提供证明/来源与可测断言。把近似演示与严格证明分开；角的方向、交点、面积、分母和参数边界应在实际构型中验证。输出供 Scene 消费的数学规格；数学不成立时不继续制作断言性成片。

## B. 教学分镜

按「引题 → 直觉/构造 → 推理或实验 → 条件下的结论 → 回顾」设计镜头，因年级与题型调整节奏。每镜写明：学习事实、画面对象和状态、字幕/旁白、预计时长、转场/对象清理、数学/布局检查点。必要时加入反例或变化后的构型；字幕不得早于相应前提出现。已有 `storyboard.md` 优先在其上审查、修订，不盲目覆盖。

## C. Manim 实现

`Scene.construct()` 负责时间编排，数学与几何纯计算尽量放在可独立测试的函数中。确认实际 Manim CE 版本及可用类；`MathTex` 处理 LaTeX 公式，中文解释使用 `Text` 等可用字体支持的对象；现有场景如需局部修改，不为了套用新规范而重写全局 `config`。updater 与 Transform 的对象生命周期要明确开始、结束和清理。9:16 和视觉安全区是本仓库现有短视频的默认设计，必须结合真实帧尺寸和实际渲染审核，而不是仅靠硬编码坐标。

## D. 代码与数学验证

先在适当环境运行 `python -m py_compile path/to/scene.py`；再对能独立抽取的计算执行纯 Python/SymPy/NumPy 断言。对分母为零、共线、重合点、奇异矩阵、无解区域等边界定义明确行为；不得以错误的占位值让退化情形表面通过。数值容差写清量纲、测试输入和依据；随机样本无法替代数学证明。记录环境、命令和结果；无测试环境时标注未运行。

## E. 低清渲染与视觉验收

在所需依赖齐备时执行 `manim -pql path/to/scene.py ActualSceneClass`；选取开场、推导关键点、动态极值/边界、结论和结尾的代表性画面，审查中文字体/LaTeX、对象生命周期、公式和点标、字幕安全区、数学表达与真实 9:16 构图。要记录实际视频文件、所检帧位置及发现的问题；语法通过不能推断渲染成功。

## F. 生产、后期和发布

示例：`manim -qh --resolution 1080,1920 path/to/scene.py ActualSceneClass`。后期处理前确认媒体许可、输入列表、视频和音轨、目标名称及不会覆盖既有文件；不要把会全仓库递归寻找 MP4 的历史脚本当作安全的单作品流水线。用 `ffprobe` 等方式核实输出时长、编码、分辨率、音轨，关联 scene/topic 与 artifact，再比较更新前后的画廊 ID、URL 和条目选择结果。移动路径必须先走[迁移流程](../architecture/migration.md)。

## 最小交接记录

每次交付写出：知识点来源与教材状态、数学条件/结论、`storyboard.md` 路径、真实 `.py` 路径和 Scene 类名、所用 Manim/字体/LaTeX/FFmpeg 版本（若已测得）、逐级检查证据、未完成项、资源来源与索引差异。只修改文档时不需要执行场景渲染，也不应把未运行命令描述为已完成。
