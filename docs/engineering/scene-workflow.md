# 数学动画制作：从命题到发布的六阶段

## A. 数学规格

写清学习目标、先修概念、定义域、条件、结论和反例/退化条件；单独给出证明或来源。示意图不能充当证明。动态几何应检查接近退化的临界状态。

## B. 分镜

按「引题 → 直觉与构造 → 推理/实验 → 结论 → 回顾」设计镜头；每镜记录要展示的数学事实、对象状态、字幕/旁白、预计时长与过渡方式。字幕不能先于图形解释建立不正确的结论。

## C. 代码结构

保留 `Scene.construct()` 作为时间编排器；数学计算、几何不变量和可复用布局尽量抽出纯 Python 函数，并由单元测试覆盖。`MathTex` 只放适合 LaTeX 的公式，中文使用 `Text` 并检查系统字体。尽量局部化 `config`，避免导入一个 Scene 时改变其他场景的全局配置；旧文件可保持现状。

## D. 静态/数学验证

先 `python -m py_compile path/to/scene.py`，再以 NumPy/SymPy 验证几何关系、尺寸和数据边界（不能将数值近似误写为严格证明）。对分母为零、共线三角形、重合点、无解区域设置明确处理。不能用错误的替代值让异常构型表面通过。

## E. 低质量预览和视觉检查

`manim -pql path/to/scene.py ActualSceneClass`；检查每个关键时间点的可读性、主体构图、相互遮挡、中文字符、公式和 9×16 画幅安全区。禁止仅凭语法通过声称动画可用。

## F. 生产与交付

`manim -qh --resolution 1080,1920 path/to/scene.py ActualSceneClass`；音频后处理先确认版权/许可、源视频轨道和输出名称，检查目标文件没有被覆盖，再提取关键帧、核验时长/编码/声音、关联 manifest 并更新画廊。记录实际执行命令和未完成检验。
